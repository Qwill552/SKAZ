# TTS-2. Скелет сервера: `/health`, `/tts`, токен, конфиг

**Цель:** сервер, который слушает порт, проверяет ключ и отдаёт по `/tts` валидный WAV —
пока что синтетический. После этого шага юзерскрипт (TTS-5) можно делать, не дожидаясь
настоящего синтеза.

---

## Отправная точка

TTS-1 закрыт: модель выбрана, голос выбран, RTF замерен, всё записано в карту. Кода нет,
спайк выброшен.

---

## Разведка

**CORS не нужен.** `GM_xmlhttpRequest` уходит из фонового контекста Tampermonkey и
preflight не шлёт. Заголовки `Access-Control-Allow-*` в этом проекте не понадобятся нигде,
кроме страницы `/setup` (TTS-8), а она живёт на том же origin. Если по дороге захочется их
добавить «на всякий случай» — значит, где-то появился `fetch`, и чинить надо его.

**Заглушка должна быть настоящим WAV.** Не пустым файлом и не нулями: юзерскрипт из TTS-5
будет проверять, что звук дошёл и играет. Синус на 440 Гц длительностью, пропорциональной
длине текста, — идеально: слышно, что дошло, и слышно, сколько.

**Токен на `/health` тоже нужен.** Соблазн оставить `/health` открытым ради удобства
велик, но тогда любой сайт сможет проверить, стоит ли у тебя эта штука, — это готовый
признак для отпечатка браузера. Отдаём 401 без ключа.

---

## Решение

### 1. Структура

```
server/
  main.py              запуск, выбор порта, конфиг
  auth.py              проверка Bearer
  backends/
    base.py            интерфейс Backend
    stub.py            синус вместо синтеза
  wavutil.py           упаковка сэмплов в WAV
config.json            создаётся при первом запуске
```

`backends/base.py` заводится **сейчас**, хотя бэкенд один:

```python
class Backend(Protocol):
    name: str
    voices: list[str]
    def synth(self, text: str, voice: str) -> bytes: ...
```

Скорости в интерфейсе нет намеренно: она делается в браузере через `playbackRate` — там
это бесплатно и качественнее, чем менять темп синтеза. Записано в решениях карты.

### 2. Конфиг

При первом запуске создаётся `config.json`:

```json
{"port": 8756, "token": "<32 байта из secrets.token_urlsafe>", "default_voice": "…",
 "idle_unload_minutes": 10, "cache_size": 50}
```

Токен генерируется `secrets`, не `random`. При старте печатается в консоль крупно, с
пояснением, куда его вставлять, — пока нет страницы `/setup` (TTS-8), это единственный
способ его получить.

Порт: пробуем 8756, занят — 8757 и далее до 8760. Реальный записываем в конфиг. Все пять
заняты — внятная ошибка, а не трейсбек.

### 3. Эндпоинты

```
GET  /health   → 200 {"ok": true, "version": "0.1.0", "backend": "stub",
                      "voices": [...], "model_loaded": false}
POST /tts      → 200 audio/wav
```

Тело `/tts`: `{"text": "…", "voice": "…"}`. Ответы об ошибках:

| Код | Когда | Тело |
|---|---|---|
| 401 | нет или неверный `Authorization: Bearer` | `{"error": "bad_token"}` |
| 400 | пустой текст после обрезки пробелов | `{"error": "empty_text"}` |
| 413 | текст длиннее 5000 знаков | `{"error": "too_long", "limit": 5000}` |
| 422 | неизвестный голос | `{"error": "bad_voice", "voices": [...]}` |
| 503 | бэкенд не готов | `{"error": "backend_unavailable"}` |

Коды фиксируются здесь и дальше не меняются: юзерскрипт (TTS-5, TTS-6) будет разбирать их
и показывать разные тексты.

**Про 5000.** Это не продуктовое ограничение, а предохранитель. Синтез блокирующий: при
RTF из TTS-1 пять тысяч знаков — это около пяти минут речи и секунды работы потока, и всё
это время сервер не отвечает. Если из-за бага в чанкинге туда улетит глава на 200 тысяч
знаков, сервер задумается на минуты, а буфер сэмплов перевалит за гигабайт и процесс
умрёт. Настоящие чанки из TTS-6 будут на два порядка короче, и пользователь этой ошибки
видеть не должен никогда — если увидел, чинить надо чанкинг.

Если предел длины входа самой модели, замеренный в TTS-1, окажется меньше 5000 — берём
его, а не пять тысяч.

Счётчика символов в интерфейсе не будет: см. решение в карте.

### 4. Слушаем только петлю

`host="127.0.0.1"`, не `0.0.0.0`. Иначе сервер виден всей локальной сети, и токен из
32 байт становится единственным, что отделяет соседа по вайфаю от чужой видеокарты.

Если когда-нибудь понадобится доступ с телефона или с Linux-коробки — это осознанное
изменение с отдельной строкой в журнале, а не умолчание.

### 5. Логи и завершение

В консоль: время, метод, путь, код, длительность. Тело запроса **не логируем** — это текст,
который человек читает, и ему там не место.

`Ctrl+C` завершает без трейсбека.

### 6. Чего этот шаг не делает

Синтеза. Ленивой загрузки и выгрузки (TTS-3), кэша (TTS-3), нормализации (TTS-4),
таймингов (TTS-7A), страницы `/setup` (TTS-8), установщика (TTS-9).

## Готово когда

- `uv run server` поднимается, печатает порт и токен.
- `/health` с ключом отдаёт JSON, без ключа — 401.
- `/tts` с ключом отдаёт WAV, который открывается плеером и звучит синусом.
- Длина синуса растёт с длиной текста.
- Все шесть кодов ошибок из таблицы воспроизводятся.
- Запуск второго экземпляра занимает следующий порт и пишет его в свой конфиг.
- `Ctrl+C` завершает чисто.
- Сервер не виден с другой машины в той же сети.

## Проверка руками

```
curl -i http://127.0.0.1:8756/health                          → 401
curl -i -H "Authorization: Bearer <токен>" …/health           → 200, JSON
curl -H "Authorization: Bearer <токен>" -H "Content-Type: application/json" \
     -d '{"text":"проверка","voice":"…"}' …/tts -o out.wav    → играет
```

1. Открыть `out.wav` плеером — должен звучать тон, а не тишина и не треск.
2. Отправить текст в десять раз длиннее — файл должен стать заметно длиннее.
3. Отправить пустой текст, текст на 6000 знаков, несуществующий голос — три разных кода.
4. Запустить второй экземпляр, не гася первый: занял 8757.
5. С Linux-коробки: `curl http://<ip-винды>:8756/health` — должно не достучаться.
6. Убедиться, что в консоли сервера нет текста запросов, только пути и коды.

## Не трогать

Ничего от Silero сюда не заносить: бэкенд `stub` существует именно для того, чтобы TTS-3
и TTS-5 можно было делать в любом порядке. Формат ответов и коды ошибок после этого шага
считаются закрытыми — их изменение ломает юзерскрипт и требует строки в журнале.
