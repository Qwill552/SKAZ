# TTS-9. Установщик Windows, автозапуск и значок в трее

> **Перед реализацией:** проведи ревью этого шага: сверь всё ТЗ с текущим кодом,
> `models.json`, `pyproject.toml` и разделом «Зафиксированные решения» в `skaz.md`.
> Кратко перечисли устаревшие или противоречивые требования и исправь их в этом файле,
> затем реализуй шаг по обновлённому ТЗ. При расхождении следуй зафиксированным решениям;
> не пересматривай их без явной просьбы пользователя. Особо проверь `onnxruntime`/`torch`,
> модель по умолчанию, лицензии и ожидаемый размер установки.

**Цель:** человек скачал zip, распаковал, кликнул `install.bat` — и через пару минут у него
открылась страница `/setup` с готовым ключом и появился значок SKAZ в системном трее.
Дальше запуском и остановкой сервера можно управлять через этот значок без терминала.

---

## Отправная точка

Работает всё: сервер, бэкенд, нормализация, юзерскрипт с панелью и связыванием. Запускается
руками через `uv run`. Windows — рабочая машина, поэтому этот установщик первый.

---

## Разведка

**Ревью 2026-09-23.** Старые требования ONNX, отсутствия torch, MIT по умолчанию и
лимита 500 МБ отменены решениями TTS-1. Текущий сервер использует CPU `torch` и `scipy`,
Python строго 3.12; по умолчанию `silero_v5_ru` / `baya` (CC-BY-NC 4.0), альтернативой
остаётся `silero_v5_cis_base` (MIT, другой набор голосов). Ориентир установки с одной
моделью — около 0.8–1.2 ГБ, свободного места на установку нужно 2 ГБ; итог измерить.
WAV не требует ffmpeg. CUDA и onnxruntime в Windows-окружение не устанавливаются.

**`uv` решает самую противную часть.** Он ставится одним бинарником, сам скачивает нужную
версию Python в свою папку и не трогает системную. Без него пришлось бы возиться с
embeddable-дистрибутивом и `get-pip`.

**SmartScreen может показать предупреждение** для неподписанного скачанного архива;
поведение зависит от настроек Windows и репутации загрузки, оно не гарантировано.
Объяснить это в README и установщике, не предлагать отключать защиту.

**Пути.** Всё в одну папку `%LOCALAPPDATA%\skaz`: код, венв, модель, конфиг. Удаление
= запустить uninstall (также убирает ярлыки). В `Program Files` не лезем.
При сохранении данных конфиг и словарь переносятся в соседнюю папку `skaz-backup-*`;
папка самой установки удаляется. При повторной установке данные можно вернуть вручную.

## Решение

### 1. Что делает `install.bat`

По порядку, с выводом каждого шага в консоль:

1. Показывает, что будет сделано и сколько весит, ждёт `Enter`.
2. Проверяет, не установлено ли уже. Установлено — предлагает обновить или выйти.
3. Скачивает `uv` в `%LOCALAPPDATA%\skaz\bin`, если его там нет.
4. `uv python install 3.12` и `uv sync --locked` — Python, кэш и окружение в той же папке;
   после успешной установки временный кэш удаляется.
5. Показывает список моделей из `models.json` с размерами и лицензиями, даёт выбрать.
   По умолчанию — `silero_v5_ru`, CC-BY-NC 4.0, некоммерческое использование;
   MIT-вариант доступен вторым, с собственным голосом по умолчанию.
6. Качает выбранную модель с прогрессом, **проверяет SHA-256**.
7. Генерирует `config.json` с токеном.
8. Спрашивает про автозапуск — **галочка, по умолчанию снята**.
9. Создаёт ярлык «SKAZ» в меню «Пуск» для запуска приложения в трее без консоли.
10. Запускает приложение в трее и сервер, затем открывает
    `http://127.0.0.1:<порт>/setup` в браузере по умолчанию.

После установки человек сразу видит ключ и инструкцию, а значок в трее остаётся доступен
для дальнейшего управления.

### 2. Автозапуск и управление из трея

Согласился — ярлык на `run.vbs` в `shell:startup`, который запускает **приложение в трее
и сервер**. Именно `.vbs` с
`WScript.Shell.Run(…, 0, False)`, а не `.bat`: иначе при каждом входе в систему мигает
чёрное окно консоли.

Отказался — ярлык автозапуска не создаём. Пользователь запускает SKAZ обычным ярлыком
из меню «Пуск»; значок в трее появляется и при таком ручном запуске. `run.bat` остаётся
для диагностики. Автозапуск можно включить и выключить позже через меню значка;
`autostart.bat`, если сохраняется, использует тот же механизм.

Сервер при этом стоит почти ничего: модель грузится лениво и выгружается через 10 минут
простоя (TTS-3). Объяснить это рядом с настройкой автозапуска.

**Значок в трее — обязательная часть TTS-9, независимо от согласия на автозапуск.**
Отдельного основного окна управления не делаем: состояние видно в подсказке и меню значка.

#### Иконка

Использовать существующий **`skaz.svg` в корне проекта** как исходник логотипа.
Подготовить из него `packaging/skaz.ico` с размерами 16, 20, 24, 32, 48 и 256 px для трея
и ярлыка; проверить читаемость на светлой и тёмной панели задач и при масштабировании.
Преобразование выполняется при подготовке ресурсов релиза, готовый `.ico` входит в архив.
Пользователю не требуется инструмент для конвертации SVG.

#### Меню значка

| Пункт | Поведение |
|---|---|
| Состояние | Неактивная строка: «Остановлен», «Запускается», «Работает» или «Ошибка запуска»; то же состояние в подсказке значка |
| Запустить сервер | Запускает остановленный сервер; недоступен при запуске и работе |
| Остановить сервер | Завершает сервер и его воркер с моделью; значок остаётся для повторного запуска |
| Перезапустить сервер | Дожидается остановки прежнего процесса и запускает новый; повторные нажатия во время операции исключены |
| Связать с браузером | При необходимости запускает сервер, дожидается готовности и открывает `/setup` на фактическом порту |
| Открыть журнал | Открывает файл журнала, в том числе после неудачного запуска |
| Запускать при входе в Windows | Галочка отражает и меняет фактическое состояние автозапуска; по умолчанию выключена |
| Выйти из SKAZ | Завершает сервер, воркер и приложение в трее, убирает значок; выбранную настройку автозапуска на следующий вход сохраняет |

Обычный ручной запуск ярлыка и запуск при входе в Windows поднимают сервер вместе со
значком. `/setup` автоматически открывается после установки и по явной команде пользователя;
при каждом входе в систему браузер открывать не нужно.

#### Жизненный цикл

Приложение в трее работает отдельно от процесса сервера. После остановки или падения
сервера значок остаётся, показывает состояние и позволяет снова запустить сервер.
При ошибке — понятное уведомление с предложением открыть журнал. Само приложение в трее
не импортирует `torch` и не загружает модель. Меню остаётся отзывчивым во время синтеза и
загрузки модели; занятый `/tts` не должен ошибочно считаться падением сервера.

Ручной запуск, автозапуск и будущий обработчик `skaz://` используют общий механизм
управления. Блокировка единственного экземпляра и передача команды уже работающему
приложению исключают второй значок и второй сервер даже при одновременных запусках.
Переход второго экземпляра сервера на соседний порт не считается решением этой задачи.
Выбор библиотеки трея и способа передачи команд делается при реализации; решение и
измеренную память приложения в простое записать в журнал `skaz.md`.

### 3. Удаление

`uninstall.bat`: завершает приложение в трее, сервер и воркер, убирает ярлыки в меню
«Пуск» и автозапуске, удаляет ключ реестра схемы
(появится в TTS-11), спрашивает про `config.json` и словарь (в них труд пользователя —
по умолчанию **оставляем**), удаляет папку.

Юзерскрипт не трогаем — он живёт в браузере, и снести его может только пользователь.
Сказать об этом в конце.

### 4. Обновление

`install.bat` на уже установленной папке: обновляет код и зависимости, **не трогает**
`config.json`, `user_dict.json` и скачанную модель. Токен сохраняется — иначе после
обновления юзерскрипт перестанет работать и никто не поймёт почему.
Перед заменой файлов завершает приложение в трее, сервер и воркер. Сохраняет выбор
автозапуска, после обновления запускает один экземпляр приложения и сервера.

### 5. Сборка релиза

В корне Windows-архива и установленной папки находятся `install.bat`, `uninstall.bat`,
`README.txt` и ровно две папки: `userscript/` и `_internal/`. В `userscript/` лежит
только `skaz.user.js`. В `_internal/` находятся сервер, установочные скрипты,
запускатели, каталог моделей и файлы зависимостей. После установки туда же
попадают Python, окружение, модели, конфигурация, словарь, логи и служебное
состояние. Тесты, скрипты сборки, готовые модели, `uv` и окружение в архив не
входят. При переходе со старой структуры установщик переносит конфигурацию,
словарь и модель в `_internal/`, обновляет ярлыки и убирает прежние служебные
файлы из корня.

### 6. Чего этот шаг не делает

Подписи кода, MSI-инсталлятора, записи в «Установка и удаление программ», автообновления,
регистрации схемы `skaz://` (это TTS-11), Linux и macOS (TTS-10).

## Готово когда

- На чистой Windows без Python установка проходит от двойного клика до открытой `/setup`.
- Первичная установка: подтверждение начала, выбор модели и снятая галочка автозапуска.
  При обновлении — подтверждение обновления; при ошибке загрузки — повтор/выход.
- Битая докачка модели ловится по SHA-256 и предлагает повторить.
- Установка без прав администратора работает.
- В путях с пробелами и с кириллицей (`C:\Users\Дима\…`) ничего не ломается.
- Повторный запуск установщика обновляет, не теряя ключ и словарь.
- Автозапуск не мигает консолью при входе в систему.
- При ручном запуске и автозапуске появляется значок из `skaz.svg`; отдельного основного окна нет.
- Через меню доступны запуск, остановка, перезапуск, `/setup`, журнал и переключение автозапуска.
- После остановки или падения сервера значок остаётся и позволяет запустить сервер снова.
- Повторный и одновременный запуск ярлыка не создаёт второй значок, сервер или воркер.
- «Выйти из SKAZ» завершает все процессы SKAZ и убирает значок.
- Меню трея отвечает во время загрузки модели и синтеза; память приложения в простое измерена.
- `uninstall.bat` не оставляет ни папки, ни ярлыка.
- В установленном окружении CPU torch и scipy, без CUDA и onnxruntime.
- Размер установки измерен, указан в журнале и сопоставлен с ориентиром 0.8–1.2 ГБ.

## Проверка руками

Хотя бы один прогон в чистой виртуалке — на своей машине половина проблем не проявится,
потому что там уже всё стоит.

1. Чистая Windows в виртуалке, без Python. Запустить установщик, пройти до конца.
2. Записать, где именно SmartScreen показал окно и что там написано, — этот текст дословно
   переезжает в README (TTS-12).
3. Проверить `uv pip list`: CPU torch и scipy; без CUDA и onnxruntime.
4. Посмотреть размер папки.
5. Перезагрузить с включённым автозапуском: консоль не мигает, значок один, `/health`
   отвечает, браузер сам не открывается. Выключить автозапуск через меню трея,
   перезайти в Windows и убедиться, что SKAZ запускается только через ярлык вручную.
6. Установить в путь с кириллицей и пробелами.
7. Прервать скачивание модели на середине (выдернуть сеть), запустить снова.
8. Запустить установщик повторно поверх рабочей установки — ключ прежний, юзерскрипт
   продолжает работать без перенастройки.
9. Удалить, убедиться, что ничего не осталось; ярлык из `shell:startup` пропал.
10. Установить, когда 8756 занят чем-то другим — должен взять следующий и записать его.
11. Через меню трея остановить, запустить и перезапустить сервер; проверить `/health`
    и чтение после каждого запуска. «Связать с браузером» открывает правильный `/setup`
    и при работающем, и при остановленном сервере.
12. Несколько раз быстро запустить ярлык. Проверить, что значок и сервер остаются в
    единственном экземпляре. Повторить при уже включённом автозапуске.
13. Завершить процесс сервера через диспетчер задач: значок должен показать ошибку,
    открыть журнал и позволить запустить сервер снова. Проверить отзывчивость меню
    при холодной загрузке модели и во время чтения.
14. Нажать «Выйти из SKAZ»: значок исчезает, `/health` не отвечает, процессов приложения,
    сервера и воркера не остаётся. Проверить удаление и обновление при работающем SKAZ.
15. Проверить иконку на светлой и тёмной панели задач при масштабе 100%, 150% и 200%.

## Не трогать

Ядро синтеза и юзерскрипт. Шаг упаковывает готовый сервер и добавляет управление его
жизненным циклом из трея. Необходимые изменения запуска и корректного завершения сервера
допустимы с записью в журнал; формат `/tts` и поведение чтения не меняются.
