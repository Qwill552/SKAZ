## Разведка

**Рассогласование версий — главный источник будущих непонятных багов.** Юзерскрипт
обновляется сам через `@updateURL`, а сервер — только когда человек скачает новый релиз и
перезапустит установщик. Значит, рано или поздно у всех будет свежий скрипт и старый сервер.
Если это не ловить, симптом будет «всё сломалось», а причина — невидимой.

**README читают ровно до первой непонятной строки.** Поэтому он начинается не с описания
архитектуры, а с гифки, где выделяют текст и он звучит. Потом три шага установки. Всё
остальное — ниже, под сворачивающимися блоками.

**Про SmartScreen надо написать раньше, чем человек его увидит.** Текст окна дословно
записан в TTS-9 — он идёт в README рядом с кнопкой скачивания, а не в разделе «Проблемы».

## Решение

### 1. Версии и совместимость

Одна версия на проект, `MAJOR.MINOR.PATCH`. `/health` отдаёт её, юзерскрипт знает свою.

Правило: **MAJOR обязан совпадать**. Не совпал — панель показывает жёлтую полосу
«Скрипт новее сервера, обнови сервер» со ссылкой на релиз, и продолжает работать, пока
может. MINOR и PATCH расходиться разрешено.

Менять MAJOR — только когда сломан формат `/tts` или `/health`. За весь v1 этого не должно
случиться ни разу.

### 2. Обновление юзерскрипта: два пути, оба нужны

**`@updateURL` и `@downloadURL`** — Tampermonkey проверяет сам, когда решит. Оба адреса
указывают на `releases/latest/download/skaz.user.js`: постоянный URL ведёт к последнему
выпущенному файлу. Фиксированный тег не обнаружил бы следующие версии, а `main` доставлял
бы незавершённые правки.

**Своя проверка в настройках** (сделана в TTS-8) — потому что на первый путь полагаться
нельзя: момент проверки выбирает браузер, и человек может месяц сидеть на старой версии, не
зная об этом. Соседний проект `Alkohole/machine-reading-text` помечает ручное обновление
как рекомендуемое, а автообновление Tampermonkey — как нет, и это разумно.

Сборка выкладывает `version.json` с версией и SHA-256 архивов. Для предложения обновления
юзерскрипт использует GitHub Releases API; локальные установщики берут суммы из `version.json`.

### 2а. Полное обновление приложения

При запуске Windows трея проверяется последний релиз и появляется окно «Обновить / Позже».
На Linux и macOS проверка и предложение идут в панели юзерскрипта при открытии страницы.
После подтверждения установщик скачивает архив своей ОС, сверяет SHA-256, обновляет файлы
и зависимости, перезапускает сервер и сохраняет ключ, словарь, модель и выбор автозапуска.
Кнопка в настройках SKAZ запускает ту же проверку. Скрипт обновляется через Tampermonkey;
при собственной проверке открывается его окно установки.

### 3. GitHub Actions

Два рабочих процесса:

- **На каждый push**: тесты нормализации (TTS-4) и таймингов (TTS-7A), линтер, проверка,
  что `uv.lock` соответствует `pyproject.toml`, синтаксис скрипта и структура архивов.
  `torch` обязателен для моделей Silero, поэтому запрещать его нельзя.
- **На тег**: собрать zip для Windows и отдельные tar.gz для Linux и macOS, посчитать SHA-256, создать релиз,
  приложить их и юзерскрипт.

Сборка не компилирует ничего — это упаковка файлов. Матрица ОС не нужна.
Внутри каждого архива лежит свой `README.txt`; Windows версия взята с рабочего стола
с добавленным кратким шагом запуска `install.bat` и новым текстом раздела «ОБНОВЛЕНИЕ».

### 4. README

Порядок разделов фиксирован и важен:

1. Одна фраза, что это. Место для записи выделение → звук → подсветка;
   пользователь пока не предоставил запись, изображение не подменяется макетом.
2. Кнопка скачивания и три шага установки. **Здесь же** абзац про SmartScreen с дословным
   текстом окна и объяснением, почему подписи нет.
3. Что нужно: около 2 ГБ свободного места при установке. Ни системный Python, ни интернет
   для чтения после установки не нужны; при установке и обновлении интернет нужен.
4. Возможности списком, коротко.
5. Сворачивающиеся блоки: как сменить голос, как добавить слово в словарь, как сменить
   хоткей, что делать, если не работает.
6. Как устроено — для тех, кто дочитал: сервер на localhost, юзерскрипт, почему не
   расширение, почему `GM_xmlhttpRequest`, почему WAV.
7. Ограничения **честным списком**: iframe не читаются, PDF не читается, диалог схемы
   появляется на каждом новом сайте, пословная подсветка оценочная, macOS не проверена
   (если так и есть), по сети работать не умеет.
8. Лицензии: код MIT, веса Silero — своя лицензия, ссылка. Раздельно и явно.
   Текущий официальный LICENSE Silero указывает CC BY-NC-SA 4.0 для `v5_ru`, а
   `v5_cis_base` лицензируется по MIT.

Пункт 7 важнее, чем кажется: список известных ограничений снимает половину issue и делает
проект похожим на честный, а не на заброшенный.

### 5. Issue-шаблоны

Форма бага спрашивает: ОС, браузер, версия сервера (`/health`), версия юзерскрипта, сайт,
на котором сломалось. Без последнего пункта половина багов невоспроизводима.

### 6. Лицензия и NOTICE

`LICENSE` — MIT на код. `NOTICE.md` — что веса не входят в раздачу, качаются при установке,
и под какой лицензией какая модель. Ссылка на `models.json` как на источник истины.

### 7. Чего этот шаг не делает

Публикации юзерскрипта на Greasy Fork, публикации в сторе расширений, сайта проекта,
телеметрии, сбора ошибок.

## Готово когда

- Тег `v1.0.0` собирает релиз с тремя архивами, юзерскриптом и `version.json`, SHA-256 приложены.
- Чужой человек по README устанавливает всё сам, ни разу не спросив.
- Рассогласование MAJOR ловится и показывается полосой, а не ломается молча.
- CI проверяет lock, синтаксис, тесты и структуру архивов.
- В README есть место для будущей записи, абзац про SmartScreen и честный список ограничений.
- Лицензии кода и весов разведены явно.

## Проверка руками

1. Дать ссылку на релиз человеку, который не участвовал в разработке, и **молча смотреть**,
   как он ставит. Каждое место, где он остановился, — правка в README.
2. Поставить старый сервер и новый юзерскрипт — полоса о рассогласовании.
3. Скачать архив с релиза, проверить SHA-256 из описания.
4. Проверить оба пути обновления: кнопкой в настройках SKAZ и кнопкой в утилитах
   Tampermonkey. Оба должны привести к одной и той же версии.
5. Создать тестовый issue по шаблону — все нужные поля на месте.
6. Прочитать README целиком с позиции человека, который не знает, что такое Tampermonkey.

## Код этого шага

Меняются версия, обновление юзерскрипта, локальный API обновления, установщики и Windows
трей. Это расширение исходного объёма TTS-12 прямо задано пользователем.
