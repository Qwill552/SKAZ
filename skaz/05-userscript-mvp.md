# TTS-5. Юзерскрипт: выделение → звук

**Цель:** выделяешь текст на любой странице, жмёшь `Alt+T` — и слышишь его голосом Silero.
Сочетание меняется в два клика. Первый шаг, после которого штукой можно пользоваться лично,
не дожидаясь остальных.

---

## Отправная точка

К началу шага работает сервер из TTS-2 и TTS-3:

```
POST /tts        {text, voice, speed} → audio/wav,  требует Authorization: Bearer
GET  /health     → {ok, version, model_loaded},     требует Authorization: Bearer
config.json      {port, token, default_voice}
```

Сервер запускается руками (`uv run server`), установщика ещё нет. Токен лежит в
`config.json` и печатается в консоль при старте — оттуда его и берём глазами.

Браузерной части не существует вовсе.

---

## Разведка

Обычный `fetch("http://127.0.0.1:8756/tts")` со страницы на `https://` не работает, и
починить это со стороны страницы нельзя. Две стены:

1. **Mixed content.** Защищённая страница не ходит по `http://`.
2. **Local Network Access.** Приехало в Chrome 142 и Edge 142 (октябрь 2025). Промпт
   вылезает именно тогда, когда публичный origin стучится в loopback, — то есть на каждом
   новом сайте заново, а сайт у нас любой.

`GM_xmlhttpRequest` обе стены обходит, потому что диспатчится из фонового контекста
Tampermonkey, а не из страницы. В документации `@connect` значение `localhost` указано явно.
**Поэтому в этом проекте `fetch` к серверу не используется нигде и никогда.**

Третья грабля вылезет уже в TTS-6, но заложиться надо сейчас: в свежих сборках Tampermonkey
запросы `GM_xmlhttpRequest` выполняются последовательно, а не параллельно. Чтобы починить
чужой баг, Tampermonkey регистрирует DNR-правило на каждый запрос и потому не может держать
больше одного в воздухе. Для одиночного запроса в этом шаге безразлично, для префетча чанков
смертельно. Обход — официальный `@require` из репозитория утилит Tampermonkey, ценой потери
progress-событий (целому WAV они не нужны).

Четвёртое: `new Audio(blobUrl)` течёт. Каждый `URL.createObjectURL` держит блоб в памяти,
пока его не отозвать. На главе ранобэ это сотни мегабайт за сеанс.

## Решение

### 1. Заголовок скрипта

```js
// ==UserScript==
// @name         SKAZ
// @namespace    https://github.com/<user>/skaz
// @version      0.1.0
// @description  Озвучивает выделенный текст локальным Silero
// @match        *://*/*
// @noframes
// @run-at       document-idle
// @grant        GM_xmlhttpRequest
// @grant        GM_setValue
// @grant        GM_getValue
// @grant        GM_registerMenuCommand
// @grant        GM_notification
// @connect      localhost
// @connect      127.0.0.1
// @require      https://raw.githubusercontent.com/Tampermonkey/utils/refs/heads/main/requires/gh_2215_make_GM_xhr_more_parallel_again.js
// ==/UserScript==
```

`@noframes` — сознательное решение: без него хоткей регистрируется в каждом рекламном
iframe, и один `Alt+T` порождает десяток обработчиков. Цена — выделение внутри фрейма
(встроенные читалки, комментарии Disqus) не берётся. Записать в журнал, пересмотреть в TTS-7.

### 2. Настройки

Четыре значения в `GM_setValue`: `baseUrl` (по умолчанию `http://127.0.0.1:8756`), `token`,
`voice`, `hotkey`. Перебора портов и страницы `/setup` в этом шаге нет — они в TTS-8.

Ввод адреса и токена — через `GM_registerMenuCommand('Настроить сервер', …)` и `prompt()`.
Некрасиво и правильно: красивая панель в TTS-8, а сейчас нельзя застрять на вёрстке.

Если `token` пуст, первый же вызов открывает тот же `prompt()` вместо запроса.

### 3. Горячая клавиша

По умолчанию `Alt+T`. **Не `Alt+T`**: у NVIDIA это сочетание открывает оверлей со счётчиком
кадров, и на машинах с их драйвером читалка будет драться с ним за нажатие.

Хранится разобранным на части, а не строкой:

```js
{ code: 'KeyT', alt: true, ctrl: false, shift: false, meta: false }
```

Сравнивается **`event.code`, а не `event.key`**. `key` зависит от раскладки: на кириллице
та же физическая клавиша даст `'е'`, и хоткей перестанет работать ровно тогда, когда он
нужнее всего — посреди чтения русского текста. `code` — это физическая клавиша, он не
меняется никогда.

Смена — пункт меню Tampermonkey «Сменить горячую клавишу». Он рисует маленький оверлей
«Нажми сочетание, Escape — отмена», вешает одноразовый `keydown` с `capture: true` и
`preventDefault`, записывает и показывает, что получилось. Два клика и одно нажатие,
как просили.

Две проверки при записи:

- **Без модификатора не принимается.** Одиночная буква будет стрелять при любом наборе
  текста. Требуем хотя бы один из `alt` / `ctrl` / `meta` (`shift` в одиночку не считается).
- **Известные конфликты — предупреждение, но не запрет.** `Ctrl+T`, `Ctrl+W`, `Ctrl+N`,
  `F5` и подобные браузер забирает себе раньше страницы: говорим, что сочетание, скорее
  всего, не сработает, и всё равно даём записать, если юзер настаивает.

### 4. Вход

Два входа, оба обязательны:

- Горячая клавиша — обработчик на `keydown` у `document`.
- Пункт «Озвучить выделенное» в меню Tampermonkey — на случай, когда сайт перехватил
  сочетание, а менять его не хочется.

Хоткей **не срабатывает**, если фокус в `input`, `textarea` или `contenteditable`: иначе
читалка выстрелит посреди набора комментария. Проверка через `document.activeElement`.

### 5. Взятие текста

`window.getSelection().toString()`, дальше нормализация пробелов (`\s+` → пробел, обрезка
краёв). Пусто — уведомление «Ничего не выделено» и выход; текста всей страницы в этом шаге
нет, он в TTS-7.

Предел **800 символов** — совпадает с предохранителем `/tts` (TTS-2), иначе выделение
801–1000 знаков пройдёт клиентскую проверку и тут же получит `413` от сервера. Длиннее —
режем по последней точке, влезающей в лимит, и говорим вслух… то есть уведомлением:
«Прочитано начало, остальное — после TTS-6». Лимит существует ровно для того, чтобы
запретить себе делать чанкинг сейчас.

### 6. Запрос и воспроизведение

```js
GM_xmlhttpRequest({
  method: 'POST',
  url: `${baseUrl}/tts`,
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${token}`,
  },
  data: JSON.stringify({ text, voice, speed: 1.0 }),
  responseType: 'arraybuffer',
  onload: (res) => {
    if (res.status !== 200) return reportError(res.status);
    const url = URL.createObjectURL(new Blob([res.response], { type: 'audio/wav' }));
    const audio = new Audio(url);
    audio.addEventListener('ended', () => URL.revokeObjectURL(url), { once: true });
    audio.play();
  },
  onerror: () => reportServerDown(),
});
```

`revokeObjectURL` в `ended` — не косметика, см. разведку. Продублировать его и в `error`
элемента, иначе битый WAV оставит блоб висеть.

Играет всегда только один кусок: новый `Alt+T` останавливает предыдущий (`pause()` + отзыв
URL) и начинает заново. Очередь — в TTS-6.

### 7. Когда сервер молчит

Молчаливая ошибка — худшее, что может быть: юзер жмёт кнопку, ничего не происходит, он
решает, что расширение сломано. Поэтому `onerror` и `status: 0` дают `GM_notification` с
текстом «Сервер чтеца не отвечает. Запусти его и попробуй снова». Кнопки запуска здесь нет —
она в TTS-11, вместе со схемой `skaz://`.

Статус 401 — отдельный текст: «Неверный ключ», и сразу открыть `prompt()` ввода.

### 8. Чего этот шаг не делает

Чанкинга, очереди, префетча, паузы, перемотки, изменения скорости, текста всей страницы,
подсветки, панели, перебора портов, установщика. Один выделенный кусок — один звук.

## Готово когда

- На обычной статье (Википедия) выделение в пару предложений озвучивается по `Alt+T`.
- То же работает на сайте с ранобэ, то есть на защищённой странице с тяжёлым фронтендом.
- Пункт меню Tampermonkey делает ровно то же самое.
- Хоткей в поле ввода не срабатывает.
- «Сменить горячую клавишу» ловит новое сочетание с первого нажатия и сразу им пользуется.
- Сочетание без модификатора не принимается, `Ctrl+T` принимается с предупреждением.
- Хоткей работает при включённой кириллической раскладке.
- Пустое выделение даёт внятное уведомление, а не тишину.
- Выключенный сервер даёт уведомление «не отвечает», а не тишину.
- Неверный токен даёт «Неверный ключ» и предложение ввести заново.
- Второй `Alt+T` во время звучания обрывает первый и начинает новый.
- После двадцати озвучек вкладка не распухла: в `chrome://memory-internals` или в Task
  Manager браузера рост памяти вкладки не накопительный.

## Проверка руками

Сервер запущен вручную, установщика ещё нет:

1. Поставить скрипт, через меню Tampermonkey вбить `baseUrl` и токен из консоли сервера.
2. Википедия, абзац, `Alt+T`. Должно заговорить в пределах секунды-двух после того, как
   модель уже подгружена (первый запрос дольше — она грузится лениво, это ожидаемо).
3. Любой сайт с ранобэ, абзац с прямой речью. Слушать не качество интонаций, а сам факт: на
   `https` не заблокировалось.
4. Открыть DevTools → Console на этой же странице. Ошибок mixed content и Local Network
   Access быть не должно **вообще** — если они есть, значит где-то остался `fetch`.
5. Кликнуть в поле поиска на странице, набрать что-нибудь с `Alt+T` внутри. Читалка молчит.
5a. Переключиться на русскую раскладку и нажать `Alt+T` (физически — та же клавиша, что
    печатает «е»). Должно сработать. Если нет — где-то сравнивается `key` вместо `code`.
5b. Сменить хоткей на `Alt+Q`, проверить. Попробовать записать просто `Q` — отказ.
    Попробовать `Ctrl+T` — предупреждение и запись.
6. Выделить полторы тысячи знаков. Читается начало, приходит уведомление про обрезку.
7. Погасить сервер, нажать `Alt+T`. Уведомление приходит быстро, а не через таймаут в
   тридцать секунд.
8. Испортить токен в настройках, нажать `Alt+T`. «Неверный ключ» плюс `prompt()`.
9. Запустить длинный кусок и нажать `Alt+T` ещё раз на середине. Первый обрывается, второй
   играет. Двух голосов одновременно быть не должно.
10. Двадцать раз подряд озвучить абзац, следя за памятью вкладки в диспетчере задач браузера.

## Не трогать

Сервер и формат `/tts` — они закрыты в TTS-2 и TTS-3. Нормализацию текста (числа,
сокращения, ударения) — это TTS-4, здесь текст уходит как есть, даже если звучит криво.
Подсветку читаемого — она в TTS-6 и TTS-7A, здесь озвучка немая для глаз.
Никакой вёрстки панелей: `prompt()` и `GM_notification` в этом шаге достаточны, и попытка
сделать «сразу красиво» — главный способ не закрыть шаг.
